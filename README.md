# 卷带修复台 · 馆藏声带路线选择

潮声档案馆的 5 人声音修复组收到旧站报时和访谈带。当前在工作簿里记录波形病征，手工复用老馆员的阈值，同一捐赠批的样段容易被分到训练和复验两边，路线理由也难随工序卡追溯。系统接收离线病征测样和有专家签认的参考标注，向修复工位交付绑定复验清单与证据的工序卡。

| 角色 | 主要页面 | 操作权限 |
|---|---|---|
| operator | 样段观测、工序卡 | 追加待修卷观测、生成工序建议 |
| reviewer | 分藏批复验、工序卡 | 封存分折清单、发起复验、签发待审卡 |
| viewer | 馆藏卷台、样段、复验、工序卡 | 查看卷、观测、得分和票据 |

## 修复组的一天

1. 08:30 在卷台找到旧站报时带 YT-26 和捐赠批 CITY-04。
2. 08:45 在离线记录 `YT-26-inspection.csv` 核对 120 秒处的 15 段间断、1 处脉冲和残留等级 2。
3. 09:00 检点 COLL-1 至 COLL-3 的 18 个签认参考段，每个捐赠批完整分到不同验证折。
4. 09:10 复验清单发现 COLL-1 有两种折号，驳回提交，统一该批样段折号。
5. 09:20 发起分折复验。工序阈值对第三折一个换盘参考段判错，三近邻采用折内标准差尺度，在本组得到更高得分。
6. 09:35 录入员为 YT26-120 生成工序卡，核对三条参考段与建议工序。
7. 10:00 复核员签卡开工，查阅员可凭样段号回查依据。

三近邻计算标准化欧氏距离，尺度来自当前训练分折的特征标准差。按距离与样段号稳定排序，三条投票，同票从近到远。同折按样段准确率计分，跨折等权。平均相同时保留易解释的阈值模型。跨捐赠批泄漏或验证折缺任一工序时拒算。固定 18 段 seed 可复算。系统处理病征计数，原始波形检测在馆内设备先完成。

## 启动与开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

前端 http://127.0.0.1:18293，API http://127.0.0.1:19293/docs，数据库端口 17793。示例账户 `operator@demo.local`、`reviewer@demo.local`、`viewer@demo.local` 均使用 `Demo2026!`。修改服务后运行 `docker compose up -d --build`，通过 `docker compose logs backend worker` 查看异常。

| 技术 | 用途和目录 |
|---|---|
| Python 3.11 / FastAPI | `backend/domain.py` 校验分折、工作卡事务 |
| PostgreSQL 16 | `backend/schema.sql` 模型、`reel_seed.py` 演示捐赠样段 |
| Python Worker | `backend/model_choice.py` 按捐赠折验证、近邻解释 |
| HTML / CSS / ES modules | `frontend/reel.js` 卷选择、折号编辑、票据签发 |
| Nginx / Redis | 静态资源、代理、登录配额 |

`.env.example` 包含端口、数据库、JWT 与演示开关。Compose 的三个命名卷是 PostgreSQL、Redis 和后台共享产物。角色与任务状态定义于 `backend/core.py` 和 `frontend/base.js`，工序代码与卡状态在 `backend/schema.sql`、`backend/model_choice.py` 和 `frontend/reel.js`。MIT 许可。

## 扩展业务

- **授权与使用**登记同卷不同用途的授权书、署名和有效期。复核员签认时检查同用途有效期重叠。撤回授权留下原因，并阻止待交付清单出库。
- **数字保存质检**以已签工序卡收集离线派生件检测清单，在保存母版和访问副本的各自政策下核验 SHA-256、时长、声道、采样率和削波计数。重制后另存新版本。
- **馆际交付**核对副本质检、同卷授权及伙伴接入范围。出库前再次检查授权；签收时比对对方提供的 SHA-256 并留回执。交付记录以登记清单为单位，音频采集与实际传输在馆内流程完成。

先在原页面签发 YT-26 工序卡，接着登记访问副本和授权，即可完成馆际交付。既有表由附加迁移保留，演示中的 YT-26 提供采集规格和馆内授权。
